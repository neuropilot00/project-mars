## 구현 순서와 합격 조건

1. **인증 통합**: 이메일 OTP를 활성 코드에서 분리하고 보존된 TOTP 구현을 통합. 새 migration 번호는 현행 목록과 충돌하지 않게 지정한다. 기능은 기본 OFF. 가입 첫 코드·복구코드 보관 확인, 로그인 재사용 차단, 복구 후 HTTP/WS 세션 폐기, 기존 이메일 로그인 보존을 실제 격리 PG/HTTP와 오류 테스트로 확인한다. raw/Bearer 대소문자·탭·복수 공백·body token의 버전 검사를 확인한다.
2. **경제 이해와 목표 연결**: 실제 판매 견적/총가격/등록비/순수령액과 초보 목표를 통합하면서 최신 자원 에스크로 반환·길드전 점수 방어를 유지한다. 신규 무료 첫 작전과 장기 생산→거래/길드 목표의 중복 팝업을 피한다. 수수료·보상 총량은 변경하지 않는다.
3. **검증 가능한 전투 선택**: 기존 첫 출격의 진형/기동 선택이 실제 전투 초반에 적용되고 일반 전투에 전파되지 않는지 확인한다. 생산물 수령→운송→결과의 다음 행동을 정확하게 연결한다. 재미 향상은 설계 가설이며 실제 사람의 반복 플레이 결과와 구분한다.
4. **스토리·모바일 UX**: 타이틀 스토리 원문/아트를 유지한다. 피날레 잔류, 반복 열기/닫기, 키보드 진입·Escape·포커스 복원, 동작 줄이기, 360/390px 및 짧은 화면을 확인한다. 인증·거래의 로딩/오류/빈 상태와 터치영역을 확인한다. 밈은 필수 기능이 아니며 기능 추가의 근거로 삼지 않는다.
5. **통합 검증·현황판**: 기능군 전체의 소스 연결/실행/미실행을 구분한 표를 갱신한다. 모든 단위 테스트 통과를 전체 게임·실기기·상업성 완료로 표시하지 않는다. 변경별 재현과 롤백 조건을 기록한다.

## 격리와 롤백

테스트는 새 Unix 소켓 전용 임시 PostgreSQL 및 명시적 더미 자격값을 사용한다. `.env`를 읽거나 서버 운영 bootstrap/스케줄러/외부 결제·메일을 실행하지 않는다. UI는 loopback의 고정 더미 또는 격리 API만 사용한다.

TOTP 사용자 생성 이후에는 테이블/암호화 키/HTTP·WS 버전 경계를 보존하지 않는 롤백을 허용할 수 없다. OFF 전환은 기존 TOTP 사용자의 로그인/세션에 영향을 주므로 운영 활성화와 별개로 다룬다. 이번 결과는 로컬 변경이며 배포하지 않는다.
