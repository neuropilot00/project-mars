# OCCUPY MARS — Ops Minimum Runbook

> 목적: 오픈데이 또는 장애 상황에서 운영자가 최소한의 공통 절차로 움직일 수 있게 하는 1차 런북

---

## 1. 이 문서의 범위

이 문서는 다음을 다룬다.
- 배포 전 확인
- 배포 후 확인
- 기본 health 판단
- 장애 시 1차 대응
- 롤백 판단

이 문서는 아직 자동화된 관제 시스템을 대체하지 않는다.

---

## 2. Tool-verified facts

- 저장소 기준 배포 흐름은 `git push origin main` 후 Railway 자동 배포다.
- 서버 실행 스크립트는 `server/package.json` 기준 `start`, `dev`만 있다.
- 테스트 공개용 `start-test.sh`는 상업 운영 기본 경로로 쓰면 안 된다.
- 관리자 API 중 일부는 `x-admin-secret` 헤더 기반이다.

---

## 3. 운영 전제

### 필수 보유물
- 운영 URL
- GitHub 저장소 접근권한
- Railway 접근권한
- DB 접근권한 또는 조회 가능한 운영자
- 관리자 시크릿

### 금지
- 테스트용 기본 비밀번호 재사용
- 터널 기반 임시 공개를 상업 운영에 재사용
- 로그/채팅/문서에 관리자 시크릿 평문 남기기

## 4. 배포 전 체크

### Git / 문서
- [ ] 현재 배포할 커밋 SHA 기록
- [ ] 직전 정상 커밋 SHA 기록
- [ ] 릴리즈 목적과 변경 파일 요약 기록
- [ ] 릴리즈 회귀 체크리스트 준비

### 운영 설정
- [ ] 관리자 시크릿 준비
- [ ] 핵심 env 누락 없음
- [ ] DB 접속 가능
- [ ] 롤백 대상 커밋 확인
- [ ] 필요 시 `TARGET_URL=https://... npm run release:check` 실행

### 사용자 영향 판단
- [ ] 경제/출금/관리자/캠페인 관련 변경 포함 여부 확인
- [ ] 포함 시 L2 리허설까지 반드시 수행

## 5. 배포 후 즉시 Health 기준

### HTTP
- [ ] 메인 URL 200 응답
- [ ] `/health` 응답 확인 (`ok`면 200, DB 장애면 503)
- [ ] `/admin` 진입 가능

### App
- [ ] 첫 화면 렌더
- [ ] 로그인 가능
- [ ] 내 영토/인벤토리/Shipyard/Campaign 중 3개 이상 정상 진입

### Admin
- [ ] 관리자 로그인 가능
- [ ] 통계 또는 핵심 조회 탭 정상

### Economy
- [ ] `/api/config` 로드 정상
- [ ] 최소 출금값 조회 정상

## 6. 장애 분류

### P0 — 즉시 오픈 중지/롤백 검토
- 메인 접속 불가
- 로그인 불가
- 관리자 핵심 탭 불가
- 경제/출금 정합성 오류
- 테스트용 비밀번호/시크릿 노출

### P1 — 긴급 수정 우선
- 영토/수확/Shipyard/인벤토리 중 핵심 1개 이상 단절
- 캠페인/온보딩 진입 불가
- 모바일 첫 세션 진행 불가

### P2 — 당일 수정 후보
- 혼합 언어
- 일부 관리자 비핵심 탭 오류
- 토스트/카피/레이아웃 불일치

---

## 7. 1차 대응 순서

1. 장애 범위를 적는다.
2. 최근 배포 SHA를 확인한다.
3. 릴리즈 체크리스트 기준 어느 축이 깨졌는지 표시한다.
4. 재현 여부를 최소 1회 확인한다.
5. 아래 둘 중 하나를 결정한다.
   - 핫픽스 가능
   - 즉시 롤백 필요

### 핫픽스 조건
- 경제/권한/오픈 경로가 아님
- 변경 범위가 작고 재현/수정/검증이 30분 안에 가능

### 롤백 조건
- P0 이슈
- 원인 불명
- 운영자가 즉시 안전성 확신 불가

---

## 8. 롤백 기준

### 롤백해야 하는 경우
- 오픈 blocker가 재발
- 관리자 인증 회귀
- 출금/잔액 정합성 이상
- 메인/로그인/핵심 루프 단절

### 실행 보조
- dry-run: `npm run rollback:plan -- <known-good-sha>`
- 로컬 적용: `npm run rollback:plan -- <known-good-sha> --apply`
- 원격 반영 포함: `npm run rollback:plan -- <known-good-sha> --apply --push`
- `--push`는 `main`에서만 허용되며 force-with-lease를 사용한다.

### 롤백 후 반드시 남길 것
- 장애 시작 시각
- 영향 범위
- 롤백 커밋 SHA
- 사용자 체감 증상
- 후속 수정 담당
