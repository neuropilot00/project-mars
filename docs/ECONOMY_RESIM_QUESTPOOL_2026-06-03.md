# 경제 재시뮬 — quest_reward_pool 폐지 GP faucet 영향 (2026-06-03, v7.354)

## 배경
quest_reward_pool(게임플레이 PP 보상 발행 throttle)을 폐지하고 게임플레이 보상을 GP 직접 지급으로 전환(mig 298). PP는 충전(deposit) 전용. 이 변경이 GP faucet에 주는 영향을 실측 설정 기반 모델로 정량화.

## 방법
- 실측 보상 파라미터를 라이브 DB settings에서 추출(`server/_sim_gp_faucet.js`, 1회성, 정리됨).
- active F2P 1인 일일 프로파일: 퀘스트 5개(free3/activity1/spending1) + 로그인 + 미션 3개+전체완료 보너스 + 채굴 1영토.
- 코호트 50명 × 7일 투영, GP 싱크(이전 fleet 재시뮬 실측)와 비교.

## 핵심 발견
1. **퀘스트 GP는 "바닥값"이 지배** (free=3/activity=8/spending=20 GP). 코드가 `max(floor, reward_pp×rate)`라 PP캡(0.05/0.3/1.0)×rate(10)=0.5/3/10 GP는 모두 바닥값 미만 → **배율과 무관하게 바닥값 지급**. 즉 예전 풀 배율(0.1~1.5)은 GP에 거의 영향 없었음.
2. **풀의 유일한 실질 게이트는 "풀 고갈 시 채굴/퀘스트 429 차단"**이었음. 미션/로그인은 애초에 풀과 무관한 고정 GP.

## 수치 (POST-제거, active F2P 1인 1일)
| 항목 | GP/day | 풀 영향 |
|---|---|---|
| 퀘스트(5개, PP예산 0.25/2.0) | 37 | 예전 풀 고갈 시 차단 |
| 로그인(평균) | 20.4 | 무관(고정) |
| 미션(3개+보너스 50) | 95 | 무관(고정) |
| 채굴(1영토) | 0.6 | 예전 풀 고갈 시 차단 |
| **합계** | **≈153** | |

- **코호트 50×7일 = 53,560 GP/week**.
- GP 싱크(실측): ship_build 328k, ship_stat_upgrade(고래) 20.27M + repair/crate/shield → **싱크(수백만~2천만) ≫ faucet(54k)**.

## 결론
1. **per-user faucet 천장은 풀 제거 전후 동일** — 퀘스트 일일캡(2.0 PP) + tier 바닥값 + 로그인/미션 고정이 binding이었지 풀이 아니었음.
2. **변화의 본질**: 풀 고갈로 차단되던 채굴/퀘스트(≈37.6 GP/user/day 상한)가 이제 안정적으로 지급. 천장은 안 오르고, F2P 실현 faucet이 throttle 없이 천장에 도달(예측 가능·안정적 UX).
3. **페그 안전**: GP는 비상환(non-redeemable) → F2P GP 누적이 USDT 페그/솔벤시와 무관. (풀의 진짜 목적이던 PP 발행 억제는, 게임플레이가 더 이상 PP를 발행하지 않으므로 불필요.)
4. **집계 경제는 여전히 강한 디플레** — fleet 싱크가 압도. 순수 F2P(비-함대)는 net GP+이나 이는 의도된 게임통화 보유이며, 의미있는 행동(함선/강화)은 GP 싱크.
5. **watch / 튜닝 레버**: 순수 F2P GP 인플레가 과하면 `quest_max_daily_per_user`(현 2.0 PP) 또는 `quest_min_gp_*` 바닥값(3/8/20) 또는 `daily_mission_*`/`daily_login_gp_rewards`를 어드민에서 하향. 미션(95 GP)이 faucet의 최대 비중이라 조정 1순위는 미션/로그인.

## 판정
**오픈베타 진행에 문제 없음.** 풀 제거는 페그/솔벤시에 무해하고(GP 비상환), 집계 디플레 유지. 게임플레이 보상이 안정적으로 지급되어 F2P 경험은 개선. 인플레 우려 시 조정 레버는 어드민 설정으로 즉시 가능.
