# OCCUPY MARS — Admin Access Policy

> 목적: 관리자 접근을 개인 기억/채팅 의존이 아니라 운영 규칙으로 관리한다.

---

## 1. Scope

이 문서는 아래를 다룬다.
- 관리자 시크릿 사용 방식
- 저장/전달 금지 규칙
- 교체/회수 절차
- 테스트/운영 경계

---

## 2. Tool-verified facts

- 현재 서버 미들웨어 `server/middleware/adminAuth.js`는 `x-admin-secret` 또는 `x-admin-key` 헤더를 받는다.
- 실제 인증 판정은 `process.env.ADMIN_SECRET`와의 일치 여부다.
- `start-test.sh`는 테스트용 로컬 런처이며 상업 운영 기본 경로가 아니다.

---

## 3. 기본 원칙

1. 운영 관리자 접근은 `ADMIN_SECRET` 기준으로 관리한다.
2. 시크릿은 평문으로 채팅/문서/스크린샷/스트림에 남기지 않는다.
3. 테스트용 접근과 운영용 접근을 분리한다.
4. 시크릿을 모르는 상태에서 임의 추정/재사용하지 않는다.
5. 유출 의심 시 즉시 교체를 기본값으로 본다.

---

## 4. Allowed / Forbidden

### Allowed
- 배포 플랫폼의 환경변수 저장소에 `ADMIN_SECRET` 저장
- 운영자 1:1 보안 채널에서만 제한적으로 전달
- 관리자 API 요청 시 `x-admin-secret` 헤더 사용

### Forbidden
- 깃 저장소 커밋
- 일반 문서에 평문 기록
- 텔레그램/공용 메신저 채팅방에 평문 전송
- 화면공유/스크린샷에 그대로 노출
- 테스트용 시크릿을 운영에 재사용

---

## 5. Storage Policy

### 운영용
- 저장 위치: Railway 등 배포 플랫폼의 환경변수
- 로컬 `.env`가 필요하면 개인 장비에만 보관
- 저장소/문서에는 절대 기록하지 않음

### 테스트용
- 운영용과 분리된 별도 값 사용
- 테스트 종료 후 유지 필요가 없으면 폐기

---

## 6. Rotation Policy

아래 경우 즉시 교체한다.
- 평문 노출이 의심됨
- 외부 협업자에게 과도하게 공유됨
- 테스트 환경에서 운영 시크릿을 사용함
- 관리자 도구 접근 흔적이 비정상적임

권장 정기 교체:
- 소프트오픈 전 1회
- 정식 오픈 직전 1회
- 운영 중 월 1회 또는 주요 사고 후 즉시

---

## 7. Incident Response

### 유출 의심 시
1. 현재 `ADMIN_SECRET` 사용 중단 판단
2. 새 시크릿 생성
3. 배포 플랫폼 env 갱신
4. 서버 재배포/재시작 확인
5. 관리자 페이지 재로그인
6. 기존 시크릿 공유 흔적 정리
7. 사고 시각 / 범위 / 교체 완료 시각 기록

---

## 8. Pre-launch Checklist

- [ ] 운영용 `ADMIN_SECRET`가 배포 플랫폼 env에만 존재
- [ ] 테스트용 시크릿과 운영용 시크릿 분리
- [ ] 최근 채팅/문서에 평문 노출 없음
- [ ] 관리자 로그인/핵심 탭 접근 테스트 완료
- [ ] 유출 시 교체 담당자/접근권한 확인 완료

---

## 9. Operator Notes

- 관리자 API가 동작하지 않으면 먼저 `x-admin-secret` 헤더 전달 여부와 `ADMIN_SECRET` env 값을 확인한다.
- 테스트 스크립트나 로컬 데모 화면에 시크릿을 다시 출력하지 않는다.
