# 에너지 실드 제작 가치 검토 — 2026-10-21

## 판정과 범위

**현재 기본 에너지 실드는 아이템 획득만 비교하면 직접 GP 구매가 제작보다 유리하다.** 제작 산출물은 같은 `shield_basic` 1개이며, 별도 품질·강화·제작 XP가 붙지 않는다. 그러나 **배정된 미수령 Daily OPS 제작 미션**의 일회성 보상이 존재하므로, 모든 플레이어 상태에서 제작이 엄격하게 열등하다고 단정하지 않는다. 미션 보상을 제외한 반복 제작의 독립적인 수요·가치는 아직 입증되지 않았다.

이 문서는 소스와 현재 격리 로컬 후보의 공개 읽기 API를 확인한 검토이다. 가격·확률·미션 보상·활성 여부·운영 설정·플레이어 자산을 변경하지 않았다. DB 쓰기, 추가 제작/구매, 새 경제 모델 실행도 수행하지 않았다. 부모 작업의 실제 제작 성공 관측과 이 검토의 읽기 증거를 구분한다.

## 현재 후보와 시드 대조

2026-10-21 `http://127.0.0.1:56134`의 `GET /api/shop/items`, `GET /api/crafting/recipes`를 인증 없이 조회했다. 이는 현재 로컬 후보의 값이며 운영 배포 전체의 설정을 뜻하지 않는다. 비인증 레시피 응답의 `canCraft:false`는 이 조회자의 재료 보유 증거가 아니다.

052는 PP 가격 2.5 × 기본 `gp_shop_multiplier=4` → 10 GP를 **일일 이용자의 접근 가능한 실드**로 의도했다고 설명한다. 제작 시드 212는 나중에 50 GP와 재료를 요구하지만, 동일 출력에 추가 가치를 주는 설명이나 보상은 없다. 이는 의도적인 고급 실드 제작이라는 근거가 아니다.

실제 구매 API는 `item_types.price_gp`를 읽는다([itemEconomyRoutes](../server/routes/itemEconomyRoutes.js):182–195). 매 구매마다 multiplier를 재계산하지 않으므로, `gp_shop_multiplier` 설정 변경만으로 기존 상품의 GP 가격이 즉시 바뀐다고 가정하면 안 된다. 제작 비용·확률·환불은 현재 recipe 행을 사용한다. 별도 global refund 설정값이 recipe의 `fail_refund_pct`를 자동 대체하지 않는다. [관리자 CRUD](../server/services/crafting.js):276–321은 recipe별 운영 수정을 허용한다.

## 비용 비교

다음은 동일 1개 실드를 얻는 비용이며, 미션·랭킹의 조건부 보상과 채굴 시간·시장 수수료·품절/등록 수량 제한은 제외한다.

| 경로 | GP 지출과 산출물 |
|---|---|
| 상점 직접 구매 | 10 GP → 실드 1개, 확률 실패 없음. 잔액·활성 상품·stack 조건은 충족해야 함 |
| 이미 보유한 재료로 제작 1회 성공 | 50 GP + 철5/실리콘3 → 같은 실드 1개 |
| 이미 보유한 재료로 제작 1회 실패 | GP 순소모 25 + 철5/실리콘3 → 산출물 0 |
| 상점에서 재료를 사서 제작 1회 성공 | 재료105 + 제작50 = **155 GP** → 같은 실드 1개 |
| 동일 기본값으로 성공까지 반복한 기대 비용 | GP만 **56.25 GP** + 평균 철6.25/실리콘3.75. 매 시도 재료를 현재 상점 묶음으로 조달하면 총 **187.5 GP/실드** |

계산: 시도당 기대 GP 순소모는 `0.8×50 + 0.2×25 = 45`; 성공률 0.8로 나누면 `45/0.8 = 56.25`. 재료 묶음105 GP도 매 시도 소비하므로 `(105+45)/0.8 = 187.5`. 실제 비용 보장이나 관측 평균이 아닌, 고정 확률·동일 가격·충분한 시도 자격을 가정한 수학적 기대값이다. 서비스 기본 시도 한도는 최근 24시간 20회([crafting](../server/services/crafting.js):126–140)라 한 세션의 무한 재시도를 뜻하지 않는다.

따라서 재료를 무료로 취급해도 GP만 56.25 대 10으로 제작의 반복 획득 비용이 높다. 재료를 플레이어 시장에서 더 싸게 사는 것만으로 이 GP 차이가 없어지지는 않는다. 반대로 상점 묶음 가격을 모든 채굴 재고의 현금 가치나 실제 시장 체결가로 간주해서도 안 된다.

## Daily OPS 예외와 한계

[dailyOps 미션 정의](../server/routes/dailyOps.js):53–56에는 다음 기본 보상이 있다.

| mission type | 목표 | 기본 GP 보상 | 현재 표준 UTC 요일 배정 |
|---|---:|---:|---|
| `craft_resource` | 제작 시도 1회 | 60 | 월요일 |
| `craft_resource_3` | 제작 시도 3회 | 150 | 수요일 |
| `craft_resource_5` | 제작 시도 5회 | 230 | 현재 요일 조합에 없음; 정의가 존재한다고 매일 배정되는 것은 아님 |

요일 조합은 [dailyOps](../server/routes/dailyOps.js):74–103이다. 60+150+230을 모든 이용자의 매일 보상이나 모든 제작의 상시 환급으로 더하면 안 된다. 기존 배정 행의 실제 `reward_gp`, 해당 UTC 날짜, 진행도, 미수령 여부가 우선한다. 기본값만 보고 현재 특정 계정이 수령 가능한 보상을 확정하지 않았다.

[crafting route](../server/routes/crafting.js):98–108은 제작 트랜잭션 COMMIT 뒤 세 미션 진행 알림을 보낸다. 성공 여부 분기가 없으므로 **정상 COMMIT된 실패 시도도** 진행도에 포함된다. 진행 알림은 비동기이며 성공 지급을 보장하지 않는다. [notifyMissionProgress](../server/routes/dailyOps.js):429–443은 그날 실제 존재하는 미완료 미션만 목표까지 증가시키며, [claim](../server/routes/dailyOps.js):324–394에서 완료·본인 소유·오늘 날짜·미수령 조건을 충족한 보상을 별도로 수령해야 GP가 지급된다.

예를 들어 배정된 제작1 미션을 아직 수령하지 않았고 진행/수령까지 성공한다면, 재료를 이미 보유한 첫 제작 성공은 제작 GP50에서 미션60을 차감한 순 GP상 +10이 될 수 있다. 그러나 철5/실리콘3의 재고 손실은 남는다. 미션을 이미 수령했거나 미배정인 반복 제작에는 이 보상이 없다. 3회 미션150도 한 번만 수령하며, 시도3회의 성공 개수는 확률 결과에 따라 달라진다.

추가 보상에 대한 경계:

- 제작 서비스는 같은 `user_items` stack에 기본 아이템을 추가한다. 제작 품질·강화·추가 출력·독립 제작 XP는 지급하지 않는다([crafting](../server/services/crafting.js):193–235).
- `trackGPSpend`는 시즌의 GP 소비 통계/점수 경로다([season](../server/services/season.js):959–964). 제작 route는 `addPassXP`를 호출하지 않으며, 산업 pass XP 대상도 별도의 frontier 생산·도착 화물·실제 수리 기록이다([season](../server/services/season.js):519–558). 제작에 pass XP가 숨겨져 있다는 근거는 없다.
- route의 optional `weeklySvc.trackProgress(...,'gp_burn',...)` 조건은 존재하지만, 현재 [weeklyChallenge export](../server/services/weeklyChallenge.js)에는 `trackProgress`가 없다. 이를 확인된 주간 보상으로 합산하지 않는다.

## 기존 경제 모델이 이 가격 관계를 입증하지 못하는 이유

[기본 모델 설명](ECONOMY_MODEL_2026-10-21.md):35과 [행동 모델](ECONOMY_BEHAVIOR_MODEL_2026-10-21.md):18,38은 recipe의 50 GP·재료5/3·성공80%를 가져왔다. 그러나 행동 운전기는 현재 직접 상점의 **10 GP 대체 구매**를 소비자의 선택으로 비교하지 않고 역할별 확률에 따라 제작한다([운전기](../server/tools/economy_behavior_sensitivity.js):229–230).

같은 운전기의 `PRICES['item:energy_shield']=70 GP`는 합성 시장의 기준 가격이며, 역할·난수 배율로 호가/매수 의향을 만든다([운전기](../server/tools/economy_behavior_sensitivity.js):14,264–268). **실제 70 GP 매수 수요, 고정 거래가, 이익 보장 또는 실제 shield stack 판매 지원의 증거가 아니다.** 직접 10 GP 구매가 가능한 이용자가 왜 더 비싼 제작/매물을 택하는지는 검증하지 않았다.

[source-market 모델](ECONOMY_SOURCE_MARKET_MODEL_2026-10-21.md):34과 [비교 결과](ECONOMY_SOURCE_MARKET_COMPARISON_FINDINGS_2026-10-21.md):47–55는 이 실드가 `user_items` stack인 반면 실제 marketplace 아이템 등록은 `item_instances`를 요구한다는 이유로 **합성 실드 판매를 미지원으로 제외**했다. 자원 시장 엔드포인트나 등록이 존재하고 원장이 보존된다는 사실은 제작 실드에 실제 구매자가 있다는 증거가 아니다. 기존 모델·seed·산출물을 이번 검토에서 수정하거나 다시 실행하지 않았다.

## 최소 권고와 밸런스 완료 조건

이번 조치는 **가격 변경 없이 이 차이를 확인 가능한 밸런스 gate로 남기는 것**이다. 미션 예외가 있으므로 recipe를 임의 폐쇄하거나 가격을 자동 재조정하지 않는다. 다음 최소 UX 수정 후보는 제작 확인에서 동일 산출물의 직접 GP 구매가·제작 GP/재료·실패 조건을 비교하고, 실제 배정된 미수령 제작 미션이 있을 때만 그 진행도/보상을 별도 표시하는 것이다. 예외가 없을 때 직접 구매 동선을 함께 제공한다. 이 문서에서 해당 UX를 구현했다고 주장하지 않는다.

후속 정책 조정이 필요하면 운영자가 의도한 제작의 역할을 먼저 결정해야 한다. **GP 비용만 조금 낮추는 것은 재료 상점105 GP와 출력 직접 가격10 GP의 충돌을 해결하지 못한다.** 이미 수정된 운영 recipe/상품 가격을 일괄 overwrite하지 말고, 명시적 정책 승인 후 코드·출력·재료·가격·확률이 모두 옛 시드와 일치하는 대상만 구분하는 버전 있는 변경을 검토한다. 기존 `user_items`, 자원, 강화 인스턴스, 완료 거래·미션·지급 보상은 보존한다.

코드가 실행되고 50 GP가 정상 차감된 것은 기능 증거다. **제작의 가치와 전체 게임 경제가 완성됐다는 판정은 아직 아니다.** 실제 D1 이용자의 상점 대체 선택, 미션 완료 후 반복 제작/재방문, 실드 실제 사용, 자원 부족과 구매, 수수료를 포함한 플레이어 간 체결·미체결·판매 소요시간을 관측해야 한다. 미션 보상 전/후, 직접 구매/제작, 신규/반복 사용자를 분리하고, 시장 등록 수나 합성 시뮬 체결을 실제 수요로 대체하지 않는다.

별도 부모 QA의 제작 후 잔액 표시 문제(화면85 GP 잔류 대 실제35 GP)는 UI 동기화 결함이다. 이 검토의 비용·보상 정책과 구분하며 수정은 부모가 배정한 first-play 작업 범위다.

## 2026-10-25 v7.508 정책 적용

이전50GP/80% 사례와 기대비용 계산은363 이전 이력이다. 새 사람 지시에 따라 [남은 개발 계획](REMAINING_DEVELOPMENT_2026-10-24.md)의 기본 소모품 확정 재료 변환을 구현했다. 레시피/출력 상품 가격이 과거 기본값과 정확히 같은 행에만 적용하고 운영자 수정값을 보존한다. 실제 재료 조달·시장 수요·장기 공급/소모는 여전히 사용자 관찰 대상이며 이전 합성 경제 모델을 새 정책의 실측 결과로 재사용하지 않는다.
