# OCCUPY MARS — 상용화 기획 초안

> Date: 2026-05-14
> Scope: 현재 구현 상태를 전제로 한 한국 사용자 대상 상용화 초안
> Grounding source: `CLAUDE.md`, `AUDIT_FINDINGS.md`, `docs/GAME_IMPLEMENTATION_PLAN_2026-05-04.md`, `docs/TERRITORY_UTILITY_PLAN_2026-05-05.md`, 실제 서버 라우트/서비스(`auth`, `onboarding`, `dailyOps`, `battleReport`, `adminEconomyRoutes`, `vip`)

## 0. 전제: 지금 코드베이스에서 이미 있는 것

상용화 논의는 "새 게임을 다시 만드는 것"이 아니라, 이미 있는 시스템을 어떤 순서로 상품화 가능한 코어로 묶느냐의 문제다.

현재 기준으로 확인된 상용화 자산:

- 웹/PWA 기반 진입점 존재 (`manifest.json`)
- 이메일 회원가입 + custodial wallet 발급 존재 (`server/routes/auth.js`)
  - 즉, 한국 유저 대상 초기 런칭에서 지갑 설치를 필수로 강제하지 않아도 됨
- 온보딩 API 존재 (`server/routes/onboardingRoutes.js`)
- 캠페인 메인퀘스트화가 상당 부분 진행됨 (`docs/GAME_IMPLEMENTATION_PLAN_2026-05-04.md`)
- 영토 생산/재료 harvest/업그레이드/섹터 컨트롤/어드민 경제 튜닝 축이 이미 존재함 (`CLAUDE.md` 최신 핸드오프)
- Daily OPS, 주간 이벤트 캘린더 존재 (`server/routes/dailyOps.js`)
- 전투 결과 리포트 서비스 존재 (`server/services/battleReport.js`)
- 어드민 경제/온보딩/리소스/Siege 모니터링 API 존재 (`server/routes/adminEconomyRoutes.js`)
- VIP 패스 시스템 존재 (`server/services/vip.js`)

즉, 현 상태는 "기초 기술 검증 단계"는 넘었고, 문제는 **기능 수를 더 늘리는 것보다 상품용 패키징과 운영 구조를 정리하는 것**이다.

## 1. 상용화 포지셔닝

## 1.1 한 줄 정의

**"매일 10~20분 접속하는 웹 기반 영토 점령/함대 성장 PvP 전략게임"**

한국 시장 기준으로는 아래처럼 잡는 편이 현실적이다.

- "하드코어 4X 대전략"으로 포지셔닝하면 진입장벽이 너무 높음
- "방치형"으로 포지셔닝하면 전투/영토/시장 시스템의 장점이 죽음
- 가장 적합한 위치는:
  - *웹에서 바로 시작 가능*
  - *짧은 세션으로도 진척이 있음*
  - *내 영토/내 함대/내 시장 자산이 남음*
  - *전투 후 리포트로 성장 판단이 가능한 전략 PvP*

## 1.2 권장 장르 문구

대외 메시지는 아래 톤이 적합하다.

- "브라우저/PWA 실시간 영토 전략"
- "픽셀 영토 소유 + 함대 육성 + 전투 리포트 PvP"
- "짧게 접속해도 누적 성장하는 웹 전략 MMO"

피해야 할 문구:

- "블록체인 게임"
- "토큰/NFT 중심 경제"
- "초대형 문명급 4X"

이유:

- 현재 auth 구조상 지갑을 내부적으로 쓸 수는 있지만, 한국 대중 유저에게 전면 노출할수록 전환율이 떨어질 가능성이 큼
- 현재 강점은 체인 서사가 아니라 **영토 소유감 + 함대 성장 + 경제 루프 + 웹 접근성**임

## 1.3 핵심 타깃

1차 타깃:

- 20~35세 남성 중심
- 모바일 MMO/전략/수집형 성장 루프 친숙 유저
- 회사/학교/이동 중 짧게 접속하는 습관형 유저
- OGame류 웹 전략, 부족전쟁류, EVE/홈월드 감성, 픽셀 아트 수집/관리 선호층

2차 타깃:

- 시장 거래/경제 운영 좋아하는 유저
- 영토 꾸미기/이름/브랜딩/길드 상징을 즐기는 유저

핵심은 "모두를 위한 게임"이 아니라,
**짧은 플레이 시간 안에 소유·성장·전투 판단을 즐기는 틈새 전략 유저**를 먼저 잡는 것이다.

## 2. 상품 구조: 무엇을 팔아야 하는가

## 2.1 기본 원칙

출시 초반 BM 원칙은 아래가 안전하다.

- 전투 승패를 현금으로 직접 파는 구조는 피한다
- 대신:
  - 시간 절약
  - 표현/브랜딩
  - 시즌 보상 확대
  - 관리 편의/QoL
  - 약한 수준의 가속
  중심으로 판다

현재 코드에 VIP가 이미 있으므로, 상용화는 **VIP 1개에 과도하게 몰지 말고 3층 BM으로 분산**하는 것이 좋다.

## 2.2 권장 수익모델 3층 구조

### A. 시즌 패스(메인 BM)

가장 먼저 붙일 메인 BM은 **시즌 패스**다.

이유:

- Daily OPS / 주간 이벤트 / 캠페인 / 전투 / 영토 루프와 자연스럽게 연결됨
- 기존 시스템을 재활용하기 쉽다
- 한국 유저에게 이해가 가장 빠름
- 과금 유저와 무과금 유저를 같은 콘텐츠 안에 두기 쉽다

권장 구조:

- 무료 트랙: GP, 재료, 기본 스킨, 전투 리포트 꾸미기 일부
- 프리미엄 트랙: 고급 코스메틱, 영토 네임플레이트, 프로필 배지, 추가 재료 팩, 시즌 한정 함대 외형
- 패스 기간: 28일 또는 42일
- 시즌 미션 소스:
  - Daily OPS 누적
  - 캠페인 챕터 진행
  - 영토 harvest/업그레이드
  - 전투 참여/승리
  - 시장 활동

### B. VIP/구독(서브 BM)

현재 `vip.js`가 이미 존재하므로 없애기보다 **재정의**하는 편이 현실적이다.

권장 방향:

- VIP를 "전투 스탯 우위"가 아니라 **생활형 구독**으로 재배치
- 제공 가치 예시:
  - 채굴/수확 예약 슬롯 +1
  - 전투 리포트 저장/공유 슬롯 확대
  - 시장 등록 편의/QoL
  - 영토 브랜딩 슬롯 확대
  - 시즌 패스 경험치 +10~15%
  - 광고/알림/정리형 편의 기능

주의:

- 현재 VIP의 `mining_boost_pct`, `gp_earn_bonus_pct`가 과도하면 초반 경제가 P2W로 인식될 수 있음
- 정식 출시 전에는 수치를 낮추거나, PvP 직접 효율이 아닌 "일일 편의 + 약한 누적 보정" 수준으로 제한하는 것이 좋다

### C. 코스메틱/브랜딩 판매(장기 안정 BM)

OCCUPY MARS는 영토, 길드, 함대, 프로필에 **표현 자산**을 붙이기 좋은 구조다.

우선순위 높은 코스메틱 상품:

- 영토 프레임 / 영토 네임플레이트 / 희귀 테두리
- 프로필 배지 / 시즌 칭호
- 함대 배너 / 기함 오라 / 전투 리포트 테마
- 길드 엠블럼 확장 옵션
- 시즌 한정 UI 스킨

이 BM의 장점:

- 밸런스를 덜 해침
- 시즌 운영과 궁합이 좋음
- 고래 매출보다 꾸준한 중과금층 확보에 유리

## 2.3 런칭 시점에는 하지 말 것

출시 초기에는 아래 BM은 보류가 맞다.

- 직접 전투력 판매 패키지
- 희귀 전함 확정 가챠
- 랜덤박스 중심 BM
- 온체인/토큰 연동 전면화
- 복수 화폐를 추가로 늘리는 BM

이유:

- 현재 게임은 경제와 전투가 아직 민감한 단계라 밸런스 붕괴 위험이 큼
- 감사 문서상 경쟁조건/경제 이슈를 대규모로 정리한 직후이므로, 먼저 안정 지표를 확보해야 함

## 3. 출시 가능한 MVP 정의

## 3.1 현재 기능을 기준으로 한 "팔 수 있는 MVP"

정식 판매/과금 전 최소 패키지는 아래다.

### 코어 루프 MVP

- 가입/로그인
- 온보딩
- 캠페인 CH1~CH3 중심 진입
- 영토 claim → 이미지 등록 → harvest
- 재료 획득 → 함선 건조/강화
- 함대 편성
- AI 전투 + PvP 입문 전투
- 전투 결과 리포트 확인
- Daily OPS 수령
- 기본 마켓 거래

즉, 출시 시점의 제품 메시지는:

**"영토를 확보하고, 자원을 캐고, 함대를 키워, 매일 전투와 거래를 반복하는 웹 전략게임"**

여기서 중요한 점:

- 지금 코드베이스에는 더 많은 시스템이 있지만,
- 상용화 MVP는 **많은 시스템을 노출하는 것**이 아니라 **한 사이클이 잘 굴러가게 하는 것**이다.

## 3.2 런칭 MVP에서 숨기거나 뒤로 미룰 것

현재 구현되어 있어도 런칭 전면 노출은 보류하는 것이 나은 것들:

- 복잡한 베팅/추첨/스테이킹 축
- 운영 난이도가 높은 대규모 거버넌스 요소
- 설명 비용이 큰 실험적 경제 사이드 시스템
- 과도하게 많은 메뉴/탭

이유:

- 한국 초기 유저는 "재미를 느끼기 전 UI 복잡도"에 매우 민감함
- 기능이 많아도 첫 30분에 의미를 이해하지 못하면 잔존으로 이어지지 않음

실무적으로는 **출시용 UI에서 탭을 줄이고, 후반 해금 방식으로 단계적 공개**가 맞다.

## 4. MVP → 출시 전략

## 4.1 단계 0: 상용화 전 정리(2~4주)

목표: 기능 추가보다 "상품으로 묶는 작업"

해야 할 것:

- 캠페인/온보딩/데일리OPS를 첫 3일 플레이 루프로 정리
- 홈 화면 CTA를 3개로 축소
  - 내 영토
  - 함대 정비
  - 오늘 할 일
- 정식 출시 빌드에서 불필요한 메뉴 숨김
- 첫 결제 상품 3개만 준비
  - 스타터팩
  - 시즌 패스
  - VIP/월정액
- 어드민 대시보드 기준 KPI 확정

출시 전 정리 단계에서 가장 중요한 결정:

**"모든 기능을 보여주지 않는다"**

## 4.2 단계 1: 클로즈드 베타/디스코드 모집(2주)

권장 규모:

- 200~500명
- 웹/PWA 직접 유입
- 전략게임 커뮤니티, X, 디스코드, 텔레그램, 지인 풀

목표 지표:

- 가입→온보딩 완료율 60%+
- 온보딩→첫 claim 전환 50%+
- 첫 claim→첫 harvest 전환 45%+
- 첫 harvest→첫 ship build 전환 30%+
- D1 30%+
- D7 10~15%+

베타 단계의 목적은 매출이 아니라:

- FTUE 막힘 구간 확인
- 경제 인플레이션 확인
- VIP/패스 거부감 확인
- PvP 스트레스 구간 확인

## 4.3 단계 2: 소프트런치(한국 한정)

추천 채널:

- 웹/PWA 단독 런칭
- 모바일 웹 최적화 강조
- 앱스토어 패키징은 후순위

이유:

- 현재 구조는 웹이 가장 자연스러움
- 빠른 패치/밸런스 수정이 쉬움
- 스토어 심사/정책 리스크를 초반에 피할 수 있음

소프트런치 목표:

- 첫 유료전환율 1~2% 확인
- 시즌 패스 구매율 확인
- VIP 유지율 확인
- 전투/시장/영토 중 어떤 루프가 잔존 핵심인지 확인

## 4.4 단계 3: 정식출시

정식출시 조건은 기능 수가 아니라 지표다.

최소 권장 조건:

- D1 35%+
- D7 12%+
- 첫 24시간 내 claim 전환 55%+
- Daily OPS 참여율 40%+
- 전투 리포트 열람률 50%+
- 결제 전환 1.5%+
- 경제 인플레이션이 주당 허용 범위 내

정식출시 패키지:

- 시즌 1 시작
- 시즌 패스 개시
- 스타터팩 1종
- VIP/월정액 1종
- 첫 시즌 코스메틱 세트

## 5. 리텐션 설계

## 5.1 리텐션의 중심은 이미 있다

현재 구조에서 리텐션 코어는 새로 만들 필요보다, 이미 있는 아래 기능을 한 줄로 이어 붙이면 된다.

- Daily OPS
- 주간 이벤트
- 캠페인 메인퀘스트
- 영토 harvest/업그레이드
- 함선 제작/강화
- 전투 결과 리포트
- 마켓 활동
- 긴급 공성/분쟁 알림

문제는 기능 부재보다 **우선순위 노출과 보상 밀도**다.

## 5.2 리텐션 루프 3단 구조

### 1) 3분 루프

로그인 직후 바로 할 수 있어야 하는 것:

- 수확
- Daily OPS 확인/수령
- 시장 확인
- 전투 리포트 확인

이 루프는 출근/통학 중 접속용이다.

### 2) 15분 루프

하루 메인 플레이:

- 캠페인 1개 진척
- 함선 1회 강화/건조
- 전투 1~3회
- 영토 업그레이드 검토

이 루프가 D1~D7 핵심이다.

### 3) 시즌 루프

장기 잔존용:

- 시즌 패스 진행
- 영토 가치 상승
- 섹터 컨트롤
- 배지/칭호/브랜딩 축적
- 길드/세력 자랑거리 축적

## 5.3 초기 7일 리텐션 설계

### Day 0
- 가입
- 첫 영토 claim
- 첫 harvest
- 캠페인 CH1 완료

### Day 1
- 재료 사용
- 첫 함선 건조
- Daily OPS 4개 중 2개 이상 달성

### Day 2
- 첫 함대 편성
- AI 전투
- 전투 리포트 확인

### Day 3
- 첫 PvP 또는 추천 전투
- 마켓 첫 등록

### Day 4~7
- 영토 업그레이드
- 캠페인 CH2~CH3 진행
- 주간 이벤트 참여
- 첫 시즌 패스 보상 체감

핵심은 "매일 새로운 시스템을 하나씩 연다"는 느낌을 주는 것이다.
기존 기능을 다 보여주면 오히려 잔존이 떨어진다.

---

## 6. 라이브옵스 설계

## 6.1 라이브옵스 원칙

운영은 대형 이벤트보다 **예측 가능한 루틴**이 먼저다.

권장 운영 단위:

- 일간: Daily OPS + 1일 버프 이벤트
- 주간: 주간 캘린더 이벤트 + 소형 경쟁 목표
- 시즌: 패스/랭킹/코스메틱

## 6.2 일간 운영

이미 `dailyOps.js`에 맞는 구조가 있으므로, 이를 중심 허브로 둔다.

일간 운영 요소:

- 4개 Daily OPS
- 오늘의 주간 이벤트 버프 노출
- 긴급 알림 1개 이하
  - 공성전
  - 내 섹터 분쟁
  - 시장 판매 완료

주의:

- 알림은 많을수록 좋은 것이 아님
- 한국 유저는 과도한 푸시에 피로도가 빠르게 쌓임
- "오늘 1~2개만 하면 된다"는 느낌이 중요함

## 6.3 주간 운영

주간 단위 추천:

- 월: 채굴 보너스
- 수: 전투 보너스
- 금: 강화 할인
- 토: 현상금/분쟁 집중

이 구조는 이미 daily ops 주간 이벤트와 잘 맞는다.
추가 개발보다 **UI에서 한눈에 보이게 정리하는 일**이 중요하다.

## 6.4 시즌 운영

시즌은 4~6주가 적당하다.

시즌 콘텐츠 예시:

- 시즌 패스
- 시즌 영토 테마
- 시즌 프로필 배지
- 시즌 함대 리포트 스킨
- 시즌 종료 시 칭호/랭킹 보상

초기에는 랭킹 경쟁보다 **수집형 시즌 보상** 중심이 안전하다.
이유는 PvP 밸런스가 완전히 안정되기 전까지 과도한 경쟁 보상이 메타를 왜곡하기 쉽기 때문이다.

## 6.5 운영자가 매일 봐야 할 지표

현재 어드민 경제/온보딩 API가 있으므로 아래를 고정 지표로 보면 된다.

- 신규 가입 수
- 온보딩 단계별 이탈률
- 첫 claim/harvest/build/battle 전환율
- Daily OPS 참여율/수령율
- 전투 수, PvP 비중, AI 비중
- 재료 발행/소각량
- GP/PP 총량 변화
- VIP 구매 수, 시즌 패스 구매 수
- 마켓 등록 수/거래 성사 수

## 7. 한국 유저 기준 보정 포인트

## 7.1 무조건 간단해야 하는 부분

한국 유저 관점에서 초반 이탈이 크게 날 부분은 아래다.

- 메뉴가 너무 많아 보이는 것
- 영문/약어/시스템 용어가 많은 것
- 지갑/체인/서명 흐름이 전면에 보이는 것
- 왜 해야 하는지 설명 없이 자유도만 높은 것

따라서 런칭 빌드 원칙:

- 로그인은 이메일 기본
- 영문 용어 최소화
- 첫 화면 CTA 3개 이하
- 캠페인이 오늘 할 일을 강하게 안내
- 첫 전투 전까지 선택지를 줄임

## 7.2 잘 먹히는 부분

반대로 한국 유저에게 강하게 먹힐 수 있는 부분:

- 내 영토/내 닉네임/내 이미지가 남는 소유감
- 짧은 세션에서도 할 일 완료되는 구조
- 강화/건조/전투 결과 리포트의 즉각 피드백
- 시즌 배지/칭호/프레임
- 거래 가능한 경제

즉, "하드코어 전략"보다
**"짧고 진척감 있는 소유형 전략 성장"**으로 해석되게 해야 한다.

## 9. 결론

OCCUPY MARS의 상용화 핵심은 새 기능 추가가 아니다.

핵심은 아래 4가지다.

- **포지셔닝:** 웹에서 바로 하는 짧은 세션 영토/함대 전략게임
- **수익모델:** 시즌 패스 + 생활형 VIP + 코스메틱 3층 구조
- **출시 전략:** 기능 확장보다 노출 축소와 FTUE/지표 검증 우선
- **리텐션/라이브옵스:** Daily OPS, 캠페인, 영토 생산, 전투 리포트를 하나의 일간 루프로 묶기

현 코드베이스는 이미 상용화에 필요한 재료를 많이 갖고 있다.
부족한 것은 시스템 수가 아니라 **상품화 우선순위와 운영형 패키징**이다.

따라서 가장 현실적인 방향은:

**"복잡한 기능을 더 붙이는 것"이 아니라, 현재 구현된 코어를 한국 유저가 이해 가능한 10~20분짜리 웹 전략 서비스로 재구성하는 것**이다.
