# 50~100척 연합전 템포·파벌 검수 — v7.514

## 검수 범위와 결론

실제 엔진과 로컬 ship_types를 사용하되 가상의 소유자·편성으로 비교했다. 각 플레이어 전함은 종류당 3척 이하, 타이탄은 제외했다. 기존 v7.513의 20% 전함 편성은 소유 한도를 넘어 밸런스 근거에서 제외한다. 동함급·비슷한 GP 제작비·수리/전자전 편성을 따로 시험하며 양쪽 진영을 교환했다. 광물 비용·건조 시간·실사용자의 편성 분포를 GP로 대신했다고 주장하지 않는다.

기본 migration 설정을 가정한 실시간 시험(120ms/틱, 6분)은 시드1 동함급 15/15, 동GP 근접 13/13, 수리/전자전 4/4 무승부였다. 동함급의 MCC↔FSP, FSP↔CV 50척/인 양방향을 시드2·3으로 반복한 8건도 무승부였다. 동일 50척/인 MCC↔FSP에서 시드2·3은 MCC가 48척, FSP가 63~66척을 잃었다. 이 차이는 유사한 가정에서 반복되었으나 다른 편성·수리·자원비용을 포함한 전체 파벌 승률이나 사용자 실전을 대표하지 않는다.

200ms 엔진 틱이 발사 후 잔여 시간을 버리므로 간격180ms와205ms가 각각 매200ms와400ms가 되는 불연속을 확인했다. 잔여 시간 보존 후보는 한 MCC-FSP 지원 편성의 손실 차이를 줄였으나 FSP 미러 손실 17:17→35:34, 수리 이벤트 352→213으로 바꾸었다. 한 시드와 제한된 지원 편성만으로 피해·수리·전자전 정책을 바꾸면 다른 구성을 해칠 수 있어 운영 전투 계산은 유지한다. 이는 해결되지 않은 밸런스 문제다.

## 시간 제한과 재생 경로

- 기본 migration의 fleet_realtime_mode=ai에서는 일반 PvP는 대개 사전계산이다. 위 120ms/6분 시험은 all 모드 또는 해당 라이브 전투를 가정한 모델이다. 운영 설정 직접 조회는 SSH 타임아웃으로 확인하지 못했다.
- 소유 한도 준수 3대3·인당50척 사전계산은 5,418틱에 종료했지만 공성 라이브 기본250ms/10분 모델은 2,401틱에서 무승부였다. 인당100척은 사전계산 5,064틱 종료, 공성 기본 모델 및 일반 라이브 기본 모델에서 각각 제한 무승부. 가상 시계는 실제 CPU·네트워크 대기 없이 산출한 최선의 경우다.
- 300척 공성 후보에서 250→60ms는 동일 시드 자동전의 승패/손실을 유지하면서 1,381초→331.44초로 줄였다. 수동 지휘 기회·목표 시간·동시 부하·운영 설정 영향은 확인되지 않아 틱/시간 제한을 변경하지 않는다. 실시간 장기전 무승부도 미해결이다.
- 사전계산 WS 방송은 5틱 또는 희소80틱 기록을 모두25ms 간격으로 내보내 600척 예시69프레임이 약1.7초였다. 틱 차이를 반영한 기본8배속과 긴 기록의 약3분 목표를 적용한다. 기록 프레임은 생략하지 않으며 Redis 스트림 잠금은 예상 방송 시간+60초다. 최소 프레임 간격10ms 때문에 매우 많은 프레임의 정확한 3분 보장은 없다.
- 저장 기록 뷰어는 실제 틱 기반 기존2배속이라 예시 5,418틱 기록이 약9분이었다. 짧은 기록은2배, 긴 기록은 기본4/8배이며 완료된 기록에서 1/2/4/8배를 선택한다. 희소 프레임 사이 함선·함대 좌표만 보간하고 HP·파괴·명중·승패는 기록 경계를 유지한다. 8배 상한상 24분 넘는 기록은 3분을 넘을 수 있다.
- WS 수신은 다음 기록을 알 수 없어 별도 지연 없는 정확한 보간을 추가하지 않았다. 서버 재시작 시 진행 중 WS 스트림의 자동 이어보기는 보장하지 않는다. 이미 저장된 기록은 뷰어에서 다시 열 수 있다.
